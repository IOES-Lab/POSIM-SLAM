# 실제 병진 시점 변화와 전체 실패 지도 대조

[English](README.md)

BlueROV2가 해저의 세 블록과 L자 벽 옆을 실제로 횡이동한 진단 기록입니다.
앞선 시험의 좁은 관측 시점 문제가 충분한 위치 변화로 해결되는지 확인하며,
생성된 점을 모두 보존합니다.

![네이티브 현장 영상과 전체 점군](full-cloud-comparison.png)

기록된 기체 자세와 소나 장착 위치로 계산한 **대상 관측 방위 변화는 62.87°**입니다.
원본 소나 193프레임 중 114개가 계획한 검사 구간에 들어옵니다. 그중 대상 중심은
113개, 상단과 평평한 해저를 가정한 전체 그림자 설계 범위는 106개에서 소나
시야 안에 있습니다. 이 기하학적 조건만으로 동일한 물리적 반사점을 계속
관측했다고 인정하지 않습니다.

두 네이티브 재생은 같은 시각의 286개 상태, 원본 IMU·압력·DVL 속도와 기존의
미지 바이어스 초기화를 사용합니다. 항법만 사용할 때 위치 RMSE는 **0.04791m**,
기존 강도 영상 추적점을 고정점 제약으로 추가하면 **0.25628m**로 커집니다.
생성된 41개 가설점 모두 [원본 지역 좌표 PLY](native-map.ply)와
[평가용 정렬 PLY](world-aligned-assessment.ply)에 남깁니다.
전체 표면 RMSE는 **0.21467m**, 최대 오차는 **0.87659m**이며,
진단용 10cm 기준을 넘는 점은 **19/41개**입니다. 지도는 불합격입니다.
10cm는 이 기록을 설명하기 위한 구분이며 해양 SLAM 전체의 공통 허용 기준이 아닙니다.

## 센서·운항과 그림

![동기화된 원본 센서와 네이티브 현장 참고 영상](sensor-comparison.png)

원본 소나는 거리 15m, 거리 셀 599개 × 수평 빔 256개, 수직 광선 256개,
수평·수직 시야 120° × 20°, 주파수 700kHz, 설정 주기 2Hz입니다.
이번 시험에는 **하향 35° 검사 장착**과 수심 1.5m에서 대상을 향하는 여섯
횡이동 경유점을 명시했습니다. 제품 기본 설정은 바꾸지 않았습니다.
실제 압력·IMU·DVL 스트림을 보존했으며, DVL 97패킷은 모두 바닥 잠금을
보고합니다. 단일 Ping 센서는 기체에 없습니다. 센서의 IMU 선언은 1,000Hz이나
0.01초 물리 스텝에서 실제 기록은 100Hz입니다. 재표본화로 측정값을 채우지 않았습니다.

위쪽 RGB와 소나는 같은 물리적 장착 위치·방향이며 시각 차이는 최대 10ms입니다.
RGB에는 **수중 시야 2m**, 조명, 강한 해저 집광무늬와 부유 입자가 적용됩니다.
아래 전체 현장 영상과 점군 비교의 참고 영상은 기록된 자세에서 별도로 렌더링했고,
안개·흡수만 껐다고 표시했습니다. 조명·집광무늬·입자·파도는 다른 위상으로
남습니다. [원본 안개 적용 전체 영상](sensor-comparison-recorded.png)도 보존합니다.
청록 화살표는 기체의 실제 전방 RGB 카메라, 주황 화살표는 소나와 같은 장착의
평가용 RGB입니다. 같은 등각 방향, 전체 높이 범위, 파랑에서 빨강으로 변하는
Turbo 색상과 64pt² 점 크기로 점군 전체를 보여 줍니다.
두 소나 재생에는 RGB·장면 메시·정답 자세를 넣지 않았습니다.

임무 운항은 Gazebo 외부 항법을 사용합니다. 네이티브 해저 계획의 최소 이격은
1.739m입니다. 별도의 연속 상자 충돌 검사는 기체 반경 0.5m 조건에서 중심선
최소 이격 2.964m를 확인합니다. 현장 호스트는 강제 종료 없이 코드 0으로 끝났고,
소유한 네 프로세스 그룹에 잔존 프로세스가 없습니다. 네이티브 재생 드라이버는
모든 상태 응답을 받고 성공 종료합니다. 기존 클라이언트의 닫기 처리는 워커를
SIGTERM(**−15**)으로 끝냅니다. 네이티브 재생 워커의 정상 코드 0 종료는 검증되지 않았습니다.

## 소스·보존과 재현

수집 시점의 앱 `06ad1d2b`, 공개 라이브러리 `7f485964`, 음향 통합 소스
`ffecee9b`를 그대로 기록합니다. 현재 POSIM #6/#31–36의 모든 헤드가 통합
소스의 조상이며 원래 PR들은 미병합입니다. 실제 로드된 음향 라이브러리 해시와
dyld 로그를 보존합니다. 분석 앱 `1e9cb573`은 공통 소스 경로 처리를 사용하고,
추정한 체크아웃 대신 실제로 가져온 패키지를 해시합니다. 원래 보고서 생성 실패의
286개 상태와 지도도 남겼으며 수정 후 항법 상태 값은 원래 값과 완전히 같습니다.
그보다 앞선 임무 시작 전 수집 도구 실패와 원본 파일도 외장 디스크에 보존합니다.
이는 데이터·출처 처리 수정이며 추정기·센서 잡음·지도 허용 기준·설치 SDK 변경이 아닙니다.

이 제한된 크기의 기록에는 모든 프레임 감사, 전체 재생 영수증, 구성요소·도구 해시,
모든 궤적 상태·점 평가와 선택한 원본 센서 NPZ가 있습니다. 원본 입력 전체는
`source-identity.json`의 외장 디스크 위치에 한 벌만 두고, `raw-input-hashes.json`에
모든 파일을 식별합니다. 큰 JSON은 결정적 무손실 gzip으로 보관하며 원래 바이트
해시는 `data-identities.json`에 있습니다. 장면 기하는
[앞선 검사 기록](../sonar-inspection-scene-20261031/README.ko.md)의 파일을 공유합니다.
해당 기록의 자산 출처와 제삼자 고지도 적용됩니다. 이 공개 기록에 비공개 앱
구현 코드는 포함하지 않습니다.

POSIM-SLAM과 NumPy가 설치된 환경에서 실행합니다.

```sh
python docs/diagnostics/sonar-translated-view-20261031/verify.py
```

검증기는 공개 도우미로 전체 상태·점 오차와 실제 관측 방위 변화를 다시 계산하고,
보존 파일과 수정 전후 재생 값의 일치를 확인합니다. 네이티브 추정이나 월드 수집을
다시 실행하지는 않습니다. 넓은 시점 변화만으로 기존 점 모델은 해결되지 않았습니다.
다음에는 같은 기록에서 지속적인 물리적 영역·경계·가림과 공유 표면 관측을 평가하고,
미결정 고각과 거리·평면·자세의 불확실성을 유지해야 합니다. 이 결과로 고정 XYZ
제약을 추가하거나 잡음 기준을 조정할 근거는 없습니다. 유용한 지도, 실제 DVL
상실·부재에서의 기여, 독립 장면과 앱·플랫폼 검증은 남아 있습니다.
